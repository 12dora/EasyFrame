# 08 · 决策记录

D1–D13 于 2026-08-11 与所有者逐条确认定案；同日经四路独立交叉评审（架构 / 数据与契约 / 安全与前端 / 下游可行性），采纳与否决记录见文末。

## 决策

**D1 · 权限分类同 EasyAuth = 共享同一权限注册表**。宿主唯一注册表推导 manifest/catalog/超管全集/校验（含防漂移测试）；本地可授集合是目录经 scope/baseline/风险规则约束后的**真子集**（⊆，非 ≡）。否决：单独维护本地权限枚举（必然漂移）。

**D2 · grant scope 化，禁 MANAGED_USERS**。`(code, scope)`，scope ∈ `supported_scopes ∩ {SELF, ALL}`。MANAGED_USERS 依赖钉钉主管链，本地用户无目录身份，属永假授权。否决：code-only（多 scope 宿主下等于隐式最大授权）；本地自建下属体系（第二套目录，越界）。

**D3 · 目录分组用点号隐式树**。`group_key` 层级由点号表达，不建组表——宿主权限量级（14–60）撑不起独立树的维护成本。

**D4 · SSO 用户与本地授权彻底隔离**。EasyAuth 是 SSO 用户唯一授权源；临时提权走 EasyAuth timed grant + 审批。本地叠加会绕过全生态审计/审批/离职交接，且破坏 fail-closed 快照语义。

**D5 · 不做本地角色层**。量级 O(10) 收益为负；前端"复制授权"补偿。重启条件：某宿主本地用户 >30 且成批同构授权。

**D6 · 授权版本化 = 自增 int + 必填 CAS**。`expectedVersion` 必填（可选即无锁）；任何 grants 变更（含 PATCH 升超管清空）都递增。不做复合摘要版本（同 DB 无跨系统失效问题）。

**D7 · 随机密码前端生成，后端只管策略**。明文在请求内瞬时处理，不持久化/不回显/不写日志审计缓存。否决：后端生成并回显（徒增泄露面）。

**D8 · 本地用户 per-app**。跨 app 统一身份是 Authentik+EasyAuth 的职责；跨宿主共享本地用户 = 自建第二套 SSO。

**D9 · 引入顺序**：主仓 v2 全量 → EasyProject 打样 → EasyTrade/EasyCustoms 同仓一次升级分别接线；下游不引入 v1 形态（EasyCustoms 存量列做一次性转换）。

**D10 · 高危操作仅超管**。扩展为操作者×目标矩阵（04 §2）：high 权限的授予**与移除**、超管创建与升降、特权目标的一切变更，均仅超管。否决：仅审计追责（权限膨胀）；仅拦 `accounts.local.*` 两个 code（边界无法解释）。

**D11 · 登录模式五态**。新增 `enabled`（生产合法常开）；`break_glass` 收紧仅超管，应急语义纯化。资格判定每请求执行，模式收紧即时生效。否决：长开 break_glass 当常开档（监控无法区分真应急）。

**D12 · 账户级有效期**。`expires_at` 可选，到期由统一资格判定即时拒绝（含存量会话）；超管禁设有效期、自我有效期禁改。否决：grant 级到期（对本地场景过设计）。

**D13 · 守卫/解析/审计逻辑下沉内核**。host-port（unit-of-work 事务契约）形式进 `enterprise_platform`，宿主薄 port，三下游零逻辑复制，platform 契约测试钉实现。

## 交叉评审记录（2026-08-11）

**采纳**（已并入各文档，此处仅列主题）：

- 操作者×目标矩阵补洞：POST 创建超管、high 权限移除、特权目标接管路径（重置密码/TOTP 救援）、自我救援 → 04 §2；
- 统一资格判定取代"仅登录时校验"，消除有效期/模式收紧的 8h 残留窗口 → 02 §4；
- 三态身份从约定升级为 DB CHECK + 规范谓词；密码认证过滤本地行；SSO 用户名冲突确定性重试 → 02 §1；
- 授权上下文改为归一化 grants 列表（放弃 `min_scope` 序数比较——MANAGED_USERS 与 SELF 无全序）；定义带类型授权主体 `(kind, id)` 与本地 SELF 语义 → 02 §3；
- 契约精化：LocalGrant 统一 DTO、重复 code 422、expectedVersion 必填、expiresAt 三态/时区/拒绝过去、audit 动作名保持已落地形式、catalog 响应含中英名、`/auth/me` 增 `isLocalSuperadmin`/`accountId` → 03/04；
- risk_level 收紧 Literal+CHECK，未知值按 high；Customs `medium` 迁移前归一 → 03 §2；
- 事实修正：权限注册表现为两份硬编码（"单一事实源"是 v2 目标不是现状）；快照有效期以上游 `expires_at` 为准而非固定 5min；seed 后置条件逐模式定义；时序均衡改为恰一次 hash；XSS 缓解如实降级为"接受的已知风险"；
- 下游现实修正：EasyProject 账户模型改造、EasyCustoms v1 存量列与静态 manifest、EasyUI submodule 需独立升级、conformance 套件需宿主参数化、业务授权解析三处接入点、每宿主唯一 JWT 密钥 + iss/aud、回滚以关闭为先 → 07。

**否决**（含理由）：

- 本地账户改软删除/墓碑：改用轻量方案——删除仅限误建未启用账户，离场走停用/到期，业务表松引用 + 审计留 username 快照（02 §6）。全量软删除的状态机复杂度对 O(10) 量级不成比例。
- `login_name`/`display_name` 拆列：v2 范围外；采纳确定性后缀 + IntegrityError 重试的轻量冲突方案，拆列列为后续候选。
- 限流外置 PG：维持已知限制（06 §2），全生态单副本，为不存在的部署形态提前付费不值。
- 迁移 expand/contract 三段式：单副本 + 启动前迁移栅栏使混合版本窗口不存在，按此简化（03 §5），但 downgrade 必须还原数据形态。
