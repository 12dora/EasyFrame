# 02 · 总体架构

## 1. 身份模型：单表三态（D4）

所有身份统一在 `platform_accounts`，两列表达三态：

| 身份 | `external_source` | `is_admin` | 密码 | 权限来源 |
|---|---|---|---|---|
| 超级管理员 | NULL | true | bcrypt hash | 宿主权限全集 |
| 本地用户 | NULL | false | bcrypt hash | 本地 grants（+ baseline） |
| SSO 用户 | `'authentik'` | false | NULL | EasyAuth 快照（唯一来源） |

三态必须是**受约束的不变量**，不能只靠约定：

- **DB CHECK**（0004 迁移）：`external_source IS NULL OR (password_hash IS NULL AND is_admin = false)`——外部行不可能持密码或超管位。
- **规范谓词** `is_local_superadmin(account)` = `external_source IS NULL ∧ is_admin ∧ local_auth_mode() ≠ disabled`，全部代码经此判定，禁止裸读 `is_admin`。
- 密码认证查询显式过滤 `external_source IS NULL`。
- 管理面只见本地行：对 SSO id 返回 404；SSO 行不可持有本地 grants；本地用户不存在于 EasyAuth。
- **用户名冲突**：`username` 全局唯一横跨两类行。OIDC upsert 冲突时用确定性后缀（`{name}-{sub[:8]}`，再冲突用全 sub）并做 IntegrityError 重试；本地创建撞隐藏 SSO 行时返回普通 409（不泄露来源）。login/display 名拆列不在 v2 范围（08 评审记录）。

## 2. 权限目录：单一注册表

v2 建立**一个**宿主权限注册表（`PermissionRegistration` 列表，`code = domain.resource.action`，含 `group_key?`、`supported_scopes`、`risk_level ∈ {standard, high}`），由它推导全部投影，并以测试钉住不可漂移：

```
宿主权限注册表 ──→ EasyAuth manifest / descriptor
              ──→ platform_permission_catalog（启动 upsert；注册表外旧 code 自动置 inactive）
              ──→ 超管权限全集（取代独立的 ALL_PERMISSIONS 常量）
              ──→ baseline / 授权校验
```

## 3. 授权解析：归一化 grant 上下文

两条通路在解析层归一为同一结构，业务代码不感知权限来源：

```
本地 grants（(code,scope) 列表）─┐
                                ├→ list[NormalizedGrant] → current_user()
EasyAuth 快照 normalize ────────┘      ├ .permissions: set[code]（兼容投影，现有 require_permission(code) 零改动）
                                       └ .grants（scope 判定用 best_scope_for_grants / subject_ids_for_scope）
```

- 归一化在**每次读取**执行：未知 code、inactive code、scope ∉ 当前 `supported_scopes`、格式坏行——一律剔除（目录收缩即时生效于存量 grants）。
- **不做** `require_permission(code, min_scope=…)` 之类序数比较：MANAGED_USERS 不含本人，与 SELF 无全序关系，scope 判定只能走 grants 结构。
- **授权主体**是带类型的 `(kind, id)`：本地 = `(local, account_uuid)`，SSO = `(authentik, sub)`。下游业务表按此松引用记录归属，`SELF` 对本地用户即匹配自身 subject；`SELF` 解析依赖 Authentik sub 且无本地对应的权限，目录中对本地标记不可授。

## 4. 统一资格判定（G10 的答案）

本地账户的资格谓词只有一个，四处执行同一份：**密码认证、二次验证完成、会话签发、每次已认证请求的 current_user 解析**。

```
eligible(account) = active
                  ∧ (expires_at IS NULL ∨ expires_at > now)
                  ∧ mode 允许：disabled→无 | break_glass→仅超管 | enabled/development/demo→全部
```

推论：模式收紧（enabled→break_glass/disabled）与账户到期对**存量会话**在下一次请求即生效——没有 8h 残留窗口。SSO 会话不受本地模式影响。模式矩阵全文只在 04 §4 维护。

## 5. 内核/宿主分层（D13）

| 层 | 职责 | v2 变化 |
|---|---|---|
| `enterprise_platform/local_accounts.py` | router factory、契约、守卫、解析、审计语义 | 守卫/校验/审计逻辑自宿主下沉至此 |
| 宿主薄 port | Account 读写、SessionLocal、审计落库 | **unit-of-work 契约**：加锁读（`with_for_update`）、grant 版本 CAS、变更与审计追加在**同一事务**提交——杜绝 v1 "变更已提交、审计另开 session" 的撕裂。platform_tests 覆盖并发降级/删除与审计写失败回滚 |
| EasyUI `enterprise-local-accounts` | surface 本体（antd） | scope/组树/能力驱动控件；宿主只写 adapter+labels |
| 宿主前端页 | 挂 surface、i18n、导航门禁 | 各宿主自有路由（见 07 §3） |

## 6. 边界（明确不做）

- 不做跨 app 门户/应用聚合；不做本地用户目录绑定或 MANAGED_USERS 本地解析；不做本地审批流（本地授权即超管直授）。
- 本地账户**删除仅用于误建且未启用的账户**；离场的标准路径是停用或到期。下游业务表对 principal 用松引用（无外键），删除后展示回落"已删除账户"，审计行保留 username 快照。
