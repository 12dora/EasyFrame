# 07 · 下游引入指南

原则：平台内核零 fork、宿主只写薄 port 与适配层、生产默认关闭、门禁先行。顺序（D9）：**主仓 v2 全量 → EasyProject 打样 → EasyTrade/EasyCustoms（一次 submodule 升级、两宿主分别接线）**，下游不经历 v1 形态（EasyCustoms 的 v1 存量列做一次性数据转换，不算引入 v1）。

## 1. 逐宿主现状与差异矩阵（2026-08-11 对照仓库核实）

| 维度 | EasyProject | EasyTrade | EasyCustoms |
|---|---|---|---|
| 账户表 | `local_admin_accounts`（全员合成超管，无 grants/expiry）→ **需模型改造迁移**（保留 passkey/会话/外键引用），`LocalAdminAuthzService` 改为调用内核解析器 | `users` 表，补列即可 | 账户表已有 v1 `local_permissions` 列（`0014_account_local_permissions.py`）→ list→object 转换 |
| 接线点 | `app/platform/router.py`（factory 组装）| `app/api/v1/platform_router.py` | `customs_app/main.py`（直接挂 FastAPI，**需自补 `/api/v1` 前缀**）|
| 模式/seed | 无 `*_LOCAL_AUTH_MODE`，seed 走 provisioning 脚本 → 需引入五态模式配置 | 运行环境门控 + `EASYTRADE_SEED_ADMIN_PASSWORD` → 对齐五态与 seed 后置条件 | `*_LOCAL_AUTH_MODE` 形态已同构 |
| manifest 流程 | SDK `sync_manifest`，版本自动推导 | S0 route-matrix 管道生成，content-hash 版本 → 在管道源头加 `accounts.local.*` | 静态 descriptor（schema_version=1，无 auto-push）→ 手工递增 + 触发 EasyAuth 抓取 |
| 风险值 | 两值合规 | 两值合规 | 注册表含 `medium` → **迁移前归一为 standard/high** |
| 前端 | `/[locale]/admin/...` 区 | `/[locale]/admin/settings/...`，请求封装为 `apiJsonRequest` | `/[locale]/app/settings/...`，同 blank 形态 |
| 测试门禁 | 无 `make *-check` → 需补建 | platform_tests 跑在独立 blank DB（不证明宿主） | 测试镜像未拷 platform_tests |

## 2. 统一步骤（每宿主的 Definition of Done）

**后端**

1. 升 submodule：`backend/easyframe` **与 EasyUI（`frontend/packages/easy-enterprise`）两个指针都要升**（v2 surface 不随后端指针到达），锁文件/构建验证。
2. 权限注册：宿主注册表加入 `accounts.local.view`（standard）/ `accounts.local.manage`（high）；manifest 按 §1 各自流程同步并**验证 EasyAuth 侧接受的版本**。
3. 迁移（宿主 alembic，基于各自当前 head）：按 §1 差异矩阵 + 03 §2 全部新列/约束/转换。
4. 薄 port 实现（unit-of-work 契约，02 §5）+ 挂载 router。
5. **业务授权解析接入**（仅挂管理 router 不够）：宿主的权限解析点必须改为消费内核归一化 grants——EasyProject `LocalAdminAuthzService`、EasyTrade 的 EasyAuth-only 解析、EasyCustoms 的"非外部账户返回空集"三处都要接本地通路。
6. 模式与 seed：接入五态 `*_LOCAL_AUTH_MODE` 与 seed 后置条件（04 §4）；**JWT 根密钥每宿主唯一 + iss/aud 绑定**（06 §2）；引入时生产保持 `disabled`。

**前端**

7. 按 §1 各自路由挂页面壳 + adapter（用宿主自己的请求封装）+ labels + 导航条目（门禁 `accounts.local.view`）。

**门禁**

8. 契约测试：从 `platform_tests/test_local_accounts.py`（现直接 import blank_app）**提取宿主参数化的 conformance 套件**，或宿主自备等价测试；写明各宿主 CI 命令。EasyProject 需先补建 check 门禁。
9. 宿主 Playwright：至少 view-only 收敛面 + 创建/授权/重置密码链路。
10. 全链路 check 绿（镜像审计、alembic heads、真实登录）。

## 3. 回滚

- **第一手段是关闭**：模式切 `disabled` + 下线导航入口——API 面即归零，不动数据。
- 代码回滚：revert 接线 PR；EasyTrade/EasyCustoms 同仓共享 submodule 指针，须两宿主一起协调。
- **不以删除已填充的授权数据为常规回滚**；alembic downgrade（含 object→string 还原）仅用于未投产环境。
- manifest 已同步的 `accounts.local.*` 权限点保留（置 inactive 即可），不回撤版本。
